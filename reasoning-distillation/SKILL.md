# Reasoning Model Distillation

Source: "Build a Reasoning Model (From Scratch)" — Chapter 8: Distilling Reasoning Models for Efficient Reasoning (Sebastian Raschka)

## Description

Hard distillation for reasoning models: training a smaller student LLM on reasoning traces and answers generated by a larger teacher LLM. Covers dataset generation from teacher outputs, answer-only cross-entropy loss (masking prompt tokens), the distillation training loop, filtering by sequence length, and evaluation. Based on the DeepSeek-R1 distillation approach.

## When to Use

- Training a smaller model to reproduce reasoning behavior of a larger model
- Implementing hard distillation (teacher text as targets, no logit access needed)
- Computing answer-only cross-entropy loss (masking prompt tokens from the loss)
- Deciding between distillation vs RLVR for improving a small model's reasoning
- Preparing teacher-generated datasets with reasoning traces

## Key Concepts

### Hard vs Soft Distillation

| Approach | Target | Requires | Practical? |
|----------|--------|----------|------------|
| **Hard distillation** | Teacher-generated tokens | Only teacher text output | Yes — most common |
| **Soft distillation** | Teacher's full probability distribution (logits) | Teacher logits at every position | Rare — logits usually unavailable |
| **Combined** | Both tokens and distributions | Both | Classical KD (Hinton et al.) |

**Why hard distillation dominates for LLMs:**
- Proprietary APIs (ChatGPT, Claude) don't expose logits
- Storing full vocab distributions (151K+ entries per token) for long traces is expensive
- Soft distillation requires matching tokenizers (same model family)
- DeepSeek-R1's smaller variants all use hard distillation

### Dataset Preparation Pipeline

1. **Generate teacher responses** on training problems (e.g., 12K math problems → DeepSeek-R1)
2. **Format**: `<think>{reasoning_trace}</think>\n\n{final_answer}`
3. **Tokenize**: prompt (with chat template) + answer (without chat template) + EOS
4. **Record prompt length** for answer-only loss masking
5. **Filter** by max sequence length (e.g., 2048 tokens)
6. **Split** into train/validation (small val set, e.g., 25 examples)

```python
def build_examples(data, tokenizer):
    examples = []
    for entry in data:
        prompt = render_prompt(entry["problem"])
        prompt_ids = tokenizer.encode(prompt)  # With chat template
        
        target_answer = format_distilled_answer(entry)  # <think>...</think>\n\nanswer
        answer_ids = tokenizer.encode(target_answer, chat_wrapped=False)
        
        token_ids = prompt_ids + answer_ids + [tokenizer.eos_token_id]
        examples.append({"token_ids": token_ids, "prompt_len": len(prompt_ids)})
    return examples
```

### Answer-Only Cross-Entropy Loss

The critical insight: only compute loss on the answer tokens, not the prompt. The prompt is context, not a target.

```python
def compute_example_loss(model, example, device):
    token_ids = example["token_ids"]
    prompt_len = example["prompt_len"]
    
    # Shift by 1: input[:-1] predicts target[1:]
    input_ids = torch.tensor(token_ids[:-1], dtype=torch.long, device=device).unsqueeze(0)
    target_ids = torch.tensor(token_ids[1:], dtype=torch.long, device=device)
    
    logits = model(input_ids).squeeze(0)
    
    # Mask prompt tokens: only compute loss on answer portion
    answer_start = max(prompt_len - 1, 0)
    answer_logits = logits[answer_start:]
    answer_targets = target_ids[answer_start:]
    
    loss = torch.nn.functional.cross_entropy(answer_logits, answer_targets)
    return loss
```

This is equivalent to negative average log probability over answer tokens only.

### Distillation Training Loop

```python
def train_distillation(model, train_examples, val_examples, device,
                       epochs=2, lr=5e-6, grad_clip_norm=1.0, seed=123, log_every=50):
    optimizer = torch.optim.AdamW(model.parameters(), lr=lr)
    model.train()
    rng = random.Random(seed)
    
    for epoch in range(1, epochs + 1):
        epoch_examples = list(train_examples)
        rng.shuffle(epoch_examples)  # Shuffle each epoch
        
        for example in epoch_examples:
            optimizer.zero_grad()
            loss = compute_example_loss(model, example, device)
            loss.backward()
            
            if grad_clip_norm is not None:
                torch.nn.utils.clip_grad_norm_(model.parameters(), grad_clip_norm)
            
            optimizer.step()
            
            # Periodic validation eval + checkpoint saving
```

Key differences from RLVR training:
- **Multiple epochs** over same data (RLVR is on-policy, single pass)
- **Cross-entropy objective** (not GRPO/reward-based)
- **Deterministic targets** (teacher tokens are fixed, not sampled)
- **Cheaper per step** (no rollout generation, no reward computation)

### Filtering by Sequence Length

Critical for hardware constraints:
```python
def filter_examples_by_max_len(examples, max_len=2048):
    return [s for s in examples if len(s["token_ids"]) <= max_len]
```

Example: 12,000 math problems with DeepSeek-R1 traces → average 2,946 tokens, max 42,005.
Filtering to 2,048 keeps 6,695 examples (55%). Keeps GPU memory at ~15 GB.

### Evaluation

After distillation, evaluate the student on a held-out test set (e.g., MATH-500):
- Use the SAME tokenizer variant (reasoning tokenizer with <think> support)
- Compare accuracy against: base model, reasoning reference, teacher model

**Typical results (Qwen3 0.6B):**
| Method | MATH-500 Accuracy |
|--------|-------------------|
| Base model (no training) | 15.2% |
| Hard distill from DeepSeek-R1, 3 epochs | 33.6% |
| Hard distill from Qwen3 235B, 1 epoch | 45.0% |
| Official reasoning model (reference) | 48.2% |
| Teacher (DeepSeek-R1 671B) | 91.2% |

### Hyperparameter Choices

| Parameter | Value | Rationale |
|-----------|-------|-----------|
| Learning rate | 5e-6 to 1e-5 | Fine-tuning range for pretrained models |
| Gradient clipping | max_norm=1.0 | Prevents instability from long sequences |
| Epochs | 2-3 | Diminishing returns after initial improvement |
| Max sequence length | 2048 | Hardware constraint (15 GB at 2048) |
| Batch size | 1 (sequential) | Simplicity; batching possible with padding |

## Design Patterns

1. **Same-family distillation outperforms cross-family**: Qwen3 235B → Qwen3 0.6B beats DeepSeek-R1 → Qwen3 0.6B (45% vs 33.6%). Tokenizer/style alignment matters.
2. **Distillation can beat RL at small scale**: DeepSeek-R1 paper showed distilled variants outperformed RL-only variants at same size.
3. **<think> tags are optional but useful**: They enable UI-level filtering of reasoning traces from final answers.
4. **One-time cost amortization**: Expensive teacher generation ($50 for 12K problems) is amortized over unlimited student training runs.
5. **Validation loss is the signal**: Training loss is noisy (per-example); validation loss on held-out set is the reliable progress indicator.

## Relationship to Our Pipeline

In our multi-stage pipeline (CPT → SFT → MGPO), distillation maps to SFT:
- Our SFT trains on gold answers (similar to hard distillation with perfect teacher)
- MGPO/RL then sharpens the calibration (precision) on top
- If we had a strong reasoning teacher, we could REPLACE our SFT stage with distillation from that teacher
- The answer-only loss masking is the SAME technique used in our `vibe_sft.py` (completion-only loss)
